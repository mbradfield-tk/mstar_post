# M-Star Post (mstar_post)
Web UI for post-processing M-Star CFD results. FastAPI backend (backend/app), React+Vite+TS frontend (frontend/src), Three.js 3D, Plotly plots.

- Backend modules: config.py (env: MSTAR_POST_ROOTS=/data:/data2, MSTAR_POST_DATA=/data/mstar/mstar_post_data), paths.py (path guards; all client paths must stay inside ROOTS), cases.py (discovery/inventory; wraps ../mstar_stats_summary/mstar_stats_summary.py), vtkio.py (memmapped .vti planes, isosurfaces, STL export with disk cache), jobs.py (SQLite queue, subprocess per job, WebSocket status; delete = remove row + run dir, rerun = wipe run dir and queue the stored commands again with the same job id, both refused while queued/running; run dirs must be inside PROJECTS_DIR; job labels are unique per project: default tasks.default_label = task + switched-on bool options + case count, duplicates get " #2", ...; optional name on the Run tab; rename = PATCH /api/jobs/{id} (Jobs tab Rename, 409 if taken, also updates job.json)), tasks.py (task registry: stats_summary, cfd_zoner, calc_ua, custom_script), routers/.
- Frontend tabs: dark/light theme from CSS variables in styles.css (:root dark, :root[data-theme="light"] light; header toggle, App sets document.documentElement.dataset.theme, localStorage mstar_post.theme, ThemeContext in theme.ts for Plotly; layers --bg < --panel < --panel-2 < --control so buttons, inputs and dropdowns stand out; use the variables, not hard-coded colors). Once opened, a tab stays mounted (App Pane, display none when hidden; key = tab|project|reset count) so its state survives tab switches; window scroll is saved per tab and a resize event is fired on switch (Plotly); Viewer3D skips rendering/resizing while hidden; Results and Plots refresh their run lists when shown (active prop) and have Reset buttons (remount; Plots also clears mstar_post.plots/means.<pid>, keeps plot style and case names). Tabs: Cases, Run, Jobs (Cancel, Re-run, Delete), Results, Plots, Viewer (SliceCanvas.tsx 2D, Viewer3D.tsx 3D, ColorLegend.tsx in-pane legend + drawLegend for PNG export, flow.ts streamlines/LIC, lic.worker.ts + lic.ts LIC Web Worker with cache), Files (FilesView.tsx, usable without a project: GET /api/fs/browse = folders + files with size/mtime + shutil.disk_usage of the file system; GET /api/fs/du = recursive allocated size like du -x, no symlinks, 30 s limit -> truncated, 10 min cache; per-folder "measure" and "Measure folder sizes" with share bars; last path in localStorage mstar_post.files.path; file viewer (FileViewer.tsx, click a file name or View; read-only, any file inside ROOTS): GET /api/fs/read?path&offset&limit&tail (256 KB chunks, max 4 MB, Start/End + Load more, UTF-8 with replacement; binary (NUL in the first 8 KB) = hex dump of 4 KB), CSV/TSV as a table (CsvTableView; .txt/.dat/.out are sniffed (sniffSep: tab , ; | with a consistent field count) so M-Star Stats .txt open as tables; table only from the file start), images via GET /api/fs/image (fixed media type, nosniff, CSP sandbox); create/delete only inside config.WRITE_ROOTS (env MSTAR_POST_WRITE_ROOTS, default /data:/data2, so case folders can be deleted by the user): POST /api/fs/mkdirs (batch, existing/invalid names skipped), /api/fs/file (new text file, never overwrites), /api/fs/delete (symlinks unlinked, non-empty folders need recursive + typed name in the UI; roots, the app and DATA_DIR and their parents refused), /api/fs/rename (same guards, same folder, never overwrites; Modify column: Rename + Delete with in-app dialogs); BatchFolders.tsx = folders from a pattern like {no}_{reactor_name}_{volume}L_{stir_speed}rpm_{note} with a row table (auto {no} start/step/digits, Excel paste, tidy separators of empty fields, duplicate/exists check)), Theory (TheoryView.tsx, usable without a project: every equation the app computes with variables, units, where used, references and HIM equation/page numbers (cite field, 2004 edition, checked against data/Handbook...pdf; data/ is git-ignored, copyrighted); equations are TeX strings (String.raw tag T`...`) rendered with KaTeX (Tex component; validate new strings with katex.renderToString throwOnError); every entry has a required vars list of [TeX symbol, meaning + unit] rendered as a symbol table, and each equation appears only once (other uses go in its "where"); app conventions without a handbook source are tagged [App] with the closest HIM analogue in cite/note; roadmap tables: HIM metrics not yet implemented (GAPS) and fluid-dynamics analyses not yet implemented (FLOW_GAPS: dissipation distribution, CFD pumping number, micromixing scales, shear distribution, dead zones, time-averaged fields/TKE, vortex depth)). Keep TheoryView in sync when adding or changing a computed metric. To search the book: pdftotext -layout to /data/mstar/.pytest-tmp/him.txt (PDF page = book page + 52 in Ch. 9-12, + 54 in Ch. 6-7, + 57 in Ch. 2).
- Plots > Time series: "Cases shown" checklist hides cases from the plot/stats (localStorage mstar_post.plots.hidden.<pid>; data of all included cases is still loaded); stacked subplot panels sharing the time axis (one Plotly figure, yaxis/yaxis2/... domains); each panel = source (case Stats .txt, or run:<name> = per-case time_s CSVs of a stats_summary run) + file + columns + moving avg + log y; Stats file/column lists are the union over all included cases, and a case missing the chosen file uses its file of the same kind holding the column (e.g. MovingBody_agitator.txt for MovingBody_Moving Body.txt); saved in localStorage mstar_post.plots.<pid>. Backend: GET /api/projects/{pid}/runs/{name}/timeseries and /series (reads <run>/<case id>/<file>; single-case projects use <run>/<case id>/ if it exists (per-case tasks like calc_ua), else <run>/ (stats_summary); holdup_profile.csv and vof_dsd.csv excluded).
- Source selects (StatsSeries and Time series panels) have exactly two categories: "M-Star Stats" and "App script outputs"; for the latter the File select lists every job's files grouped by job (optgroup, value "<run>|<file>"), internal src stays "stats" / "run:<name>".
- One-case Stats time series: StatsSeries.tsx (case + source (M-Star Stats files or run:<name> = any job's per-case time-first CSV such as calc_ua's ua.csv; run CSV time column "time [s]"/"time_s" matched case-insensitively by _is_time) + file + variables, one subplot per variable, moving avg, user averaging window from/to [s] with last 50%/25%/whole-run presets, shaded on the plot with dotted mean lines; mean/std/CoV/min/max/n over the window + last value, CSV; localStorage mstar_post.statsseries.<pid> incl. tFrom/tTo) used as Plots mode "Case time series" and in Results as the collapsible "Stats time series of one case" card. Plots mode buttons have a one-line description (MODE_HELP).
- Case display names: project.json "aliases" {case id: name} (PATCH /api/projects/{pid} {aliases}, replaces the map, unknown ids/empty dropped, names unique else 422); edited with CaseNames.tsx (Auto-shorten drops name parts shared by all ids) in Results (case tables) and Plots; caseName(project, id) is used for table case columns, bar x labels, trend labels, time-series legends, case checklists and exported selection CSVs (CSV files on disk and the script's HTML plots keep the ids).
- Plots > Plot style (PlotStyle.tsx, localStorage mstar_post.plotstyle.<pid>): plot background (plotTheme: as app theme (default) / dark / light for reports; applied in Plot.tsx themed() to paper/plot/axes/text, also in exports), font, text/title/tick sizes, x/y tick angles, legend position, grid, line width, marker size, height factor, PNG scale, bar/% bar colors, bars colored by case, case palette + per-case color overrides (color index = position in project.cases, same in all plot modes); Plot applies it via the style prop (styleLayout merges into every [xy]axis* key).
- Plots reference case: header select (localStorage mstar_post.plotref.<pid>, default project.ref_case, cleared by Plots Reset) used by every "% vs ref": bars (Show values / values + % / % only, ref bar outlined, optional % difference heatmap, exported in the selection CSV), Time series panels (vs ref: values / difference / % difference, ref interpolated onto each case's times after the moving average; steady stats table % vs ref mean) and Case detail mode (CaseDetail: one case vs the ref per variable with rank, min/max/mean/z over the checked cases, |%| filter, largest-difference bar chart, CSV); the ref row comes from all merged cases, so an excluded ref still works.
- Plots > Compare means / Trend (x-y): sources = checklist of *_means.csv and *_settings.csv over all runs, merged into one row per case (union of columns; a case in several sources takes per column the first listed source's value) plus a case include checklist; sources and excluded cases saved in localStorage mstar_post.means.<pid>.
- Viewer: Refresh button (sidebar top) = GET /api/projects/{pid}?refresh=true (cases.forget drops the 60 s case-info and 30 s inventory caches) and remount of the Viewer pane. Up to 4 cases (first = reference: drives outputs, time, 3D toggles; others use the nearest time). One row per case with 2D slice and 3D view side by side at equal height; shared color range over all shown planes. Extra views (sidebar section, up to 6): additional 2D + 3D rows for one selected case with their own field/component, colormap, log scale and color range (shared: extras of the same field share a range, the main range when it is the main field; own 1-99th pct; own min-max; manual), same output, time, plane and mask; not persisted. Each 2D/3D pane has its own overlay legend; the pane PNG buttons export image + overlays + legend (2D upscaled to >= 1200 px). Sidebar sections (Cases, Plane, Flow, 3D) collapse/expand (state in localStorage mstar_post.viewer.section.<id>). Masked solid cells use the 3D background color in 2D and 3D. 2D and 3D panes have a fixed-height toolbar (.pane-bar) above the plot so both plot areas align. 2D: wheel zoom at the cursor (0.2x to 40x; below 1 the plot shrinks), drag to pan when zoomed, +/-/1:1 buttons (CSS transform on .slice-stack; PNG export is always the full plane). 3D: XYZ axes gizmo in the bottom-left corner (second render pass with scissor; included in PNG); optional "center planes (all 3 axes)": x = 0 and z = 0 planes plus a y plane at the fluid-region center (GET /api/case/fluid_center = bounds of cells whose volume fractions sum >= 0.5, cached) or a user y, drawn via Viewer3D extraPlanes; Rotate/Pan/Box zoom modes (Pan = left-drag pans; Box zoom = drag a rectangle, one-shot), Plane button looks straight at the slice (pan then moves along it), cameras independent by default (optional "link cameras" via CameraSync), +/- zoom buttons, wheel zooms to the cursor, double-click sets the rotation center, background color (localStorage mstar_post.viewer.bg). Flow fieldset: vector array, 2D overlay none/streamlines/LIC/LIC+streamlines (in-plane components from GET /api/case/plane_vec = u plane then v plane; streamlines traced and LIC computed in the browser, LIC also textures the 3D plane), 3D streamlines seeded on the current plane (GET /api/case/streamlines, vtkStreamTracer RK4, binary, disk cache cache/stream/, stride 2 for files > 400 MB; colored by speed when the field is that vector's magnitude).
- Case folders are read-only for jobs: every output goes to the project folder under MSTAR_POST_DATA; only the user may create/delete in case folders via the Files tab. /data2 is nearly full: no app outputs there.
- Moved/renamed data: project responses carry root_missing and per-case missing (_status in routers/projects.py); Relocate.tsx (banner above the project tabs) calls POST /api/projects/{pid}/relocate {root?, cases?: {id: new folder}}; a new root moves every case under the old root, case ids are kept (runs, aliases, ref case stay linked); then Viewer and Plots are remounted.
- mstar_stats_summary.py is called as a subprocess with --batch --output-root <run dir> --cases <relative ids>. Per-case outputs land in <run>/<case id>/.
- mstar_stats_summary.py time series per case: dispersion_timeseries.csv (time_s, A_int, V_liq, a, E = a/a0, a_norm, int_a, d32 interface, eps, Hinze d_max and d_max/dx), vof_structures.csv, phase_uniformity.csv, phase_continuity.csv.
- Units: every output column/variable carries "[unit]"; dimensionless values show their dimensions, never "-" (E and a_norm (1/m)/(1/m); phase fractions, CoV, S, share, F_disp m^3/m^3; coverage m^2/m^2; d/dx m/m; counts [count]; Power Number W/W). Per-frame CSV headers come from mss.ts_label (first column "time [s]"; the app also accepts legacy "time_s"); M-Star Stats names with [-] are relabelled by mss.fix_unit (summaries, plots, app Stats series). Old results: `mstar_stats_summary.py <results dir> --migrate-units [--ref-case X]` rewrites CSV headers/units in place (idempotent) and regenerates the *_means.html. VTK arrays with "(-)" get m^3/m^3 (fractions), id or code in vtkio.unit_of. No plateau no longer drops results: flow without a mean-velocity plateau averages the last max(window, 25%) of the run (steady_method "fallback (not steady)"); a(t)/S(t) kinetics without a plateau use the last-window mean ("... (no plateau, last window)"); series_row falls back to the last samples when none are after the start time.
- Case settings (case_settings, *_settings.csv, Cases tab) include per impeller the <diameter> from input.xml, D/T, tip speed, Re = N D^2/nu_c, Fr, We = rho_c N^2 D^3/sigma, Vi = (rho_c/rho_d)^0.5 mu_d N D/sigma and the d32 correlations HIM eq. (12-30) D 0.053 (1 + 3 phi) We^-0.6 and eq. (12-28) D 0.053 We^-0.6 (1 + 0.92 Vi^0.84)^0.6 (dimensionless_groups; continuous phase = fluid with the larger initial volume, phi = initial dispersed fraction), plus tank T (smaller horizontal domain extent) and H = V/(pi T^2/4) (tank_geometry), and the simulation time: input runtime (<system><runtime>), simulated end time (Fluid.txt), iterations and wall time (Timing.txt "Cumulative Wall Time [min]", summed over restarts; run_timing). Cases tab shows them as columns plus a totals line (simTimeSummary); Results shows a per-run "Simulation time" table (SimTimeTable, cases from run.params.cases).
- power_metrics (rows with file "derived"): impeller power P = |torque . axis| |omega| from MovingBody_<impeller name>.txt, P/V, P/M, resolved/power dissipation ratio, eps_max ~ P/(rho_c D^3) (HIM eq. 2-19), Kolmogorov scale at mean resolved eps and eps_max, Hinze d_max at eps_max, Po from torque, blend-time correlation t95 (HIM eq. 9-1, constant 5.20, valid Po^(1/3) Re > 6370). vof_structures adds d_max/d32 per frame and dsd_shape the volume mean/std of d/d32 (HIM eq. 12-29: 1.07, 0.24).
- M-Star layout: <case>/input.xml, <case>/out/Stats/*.txt, <case>/out/Output/<Kind>/block0/*.<time>.vti|vtp; Volume .vti files are raw appended, uncompressed, UInt64 header.
