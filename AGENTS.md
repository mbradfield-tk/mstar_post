# M-Star Post (mstar_post)
Web UI for post-processing M-Star CFD results. FastAPI backend (backend/app), React+Vite+TS frontend (frontend/src), Three.js 3D, Plotly plots.

- Backend modules: config.py (env: MSTAR_POST_ROOTS=/data:/data2, MSTAR_POST_DATA=/data/mstar/mstar_post_data), paths.py (path guards; all client paths must stay inside ROOTS), cases.py (discovery/inventory; wraps ../mstar_stats_summary/mstar_stats_summary.py), vtkio.py (memmapped .vti planes, isosurfaces, STL export with disk cache), jobs.py (SQLite queue, subprocess per job, WebSocket status; delete = remove row + run dir, rerun = wipe run dir and queue the stored commands again with the same job id, both refused while queued/running; run dirs must be inside PROJECTS_DIR; job labels are unique per project: default tasks.default_label = task + switched-on bool options + case count, duplicates get " #2", ...; optional name on the Run tab; rename = PATCH /api/jobs/{id} (Jobs tab Rename, 409 if taken, also updates job.json); every job records `user` = the logged-in account (auth.current_user; see Identity), cleaned by jobs.clean_user, fallback = server account (getpass); rerun re-attributes to the re-running user; stored in the jobs table (ALTER TABLE on old DBs), job.json and the runs listing; shown on Jobs cards/detail, Results run list and the run overview), tasks.py (task registry with Task.group "base" | "addon": stats_summary (base: steady means, mixing, power metrics, settings, plots; no dispersion params any more), dispersion (add-on "Liquid-liquid dispersion": same script with --dispersion [--uniformity] --addons-only so only the *_dispersion/*_uniformity tables, per-case time series are written; Task.launcher = "stats_summary" so the root launcher's helper.conf entry is shared), calc_ua, cfd_zoner, custom_script; the Run tab lists Base and Add-ons and hints when the base summary is missing for the selected cases), routers/.
- Frontend tabs: the app starts on the Dashboard (Dashboard.tsx: project cards with selected/total cases, run count, created date, Open/Delete, "last opened" from localStorage mstar_post.project; project metadata owner / program (= "Associated project", e.g. TAK-360) / purpose: project.json keys, META_KEYS in routers/projects.py, <= 80 chars, owner = the logged-in account at creation (plus `created_by`), immutable afterwards (PATCH with a different owner -> 403; ProjectMetaEditor and the New project form show it read-only) and ProjectMetaEditor (ProjectMeta.tsx, META_FIELDS, shown on the Cases tab, datalist suggestions from existing values); dashboard shows them as clickable chips and has per-field select filters + text search (localStorage mstar_post.dashboard.filters); App state home=true, brand or "Projects" button returns to it, project panes stay mounted but hidden). Opening a project lands on Cases, where the user selects the cases to work on (project.cases[].included, persisted via PATCH; the Cases header/table say "selected"). Only selected cases are used by Run (job cases), Plots (Time series panels, Compare means/Trend/Case detail: rows of deselected cases are dropped with a "N not selected" note, reference select lists selected cases + the current ref), Viewer and StatsSeries (falls back to all cases if none is selected); Results run overviews show the cases of that run. Dark/light theme from CSS variables in styles.css (:root dark, :root[data-theme="light"] light; header toggle, App sets document.documentElement.dataset.theme, localStorage mstar_post.theme, ThemeContext in theme.ts for Plotly; layers --bg < --panel < --panel-2 < --control so buttons, inputs and dropdowns stand out; use the variables, not hard-coded colors; no window.confirm/prompt: use useDialog() from Dialog.tsx (render ui.dialog, await ui.confirm/ui.prompt)). Once opened, a tab stays mounted (App Pane, display none when hidden; key = tab|project|reset count) so its state survives tab switches; window scroll is saved per tab and a resize event is fired on switch (Plotly); Viewer3D skips rendering/resizing while hidden; Results and Plots refresh their run lists when shown (active prop) and have Reset buttons (remount; Plots also clears mstar_post.plots/means.<pid>, keeps plot style and case names). - Units: every output column/variable carries "[unit]"; dimensionless values show their dimensions, never "-" (E and a_norm (1/m)/(1/m); phase fractions, CoV, S, share, F_disp m^3/m^3; coverage m^2/m^2; d/dx m/m; counts [count]; Power Number W/W). Old results: `mstar_stats_summary.py <results dir> --migrate-units [--ref-case X]` rewrites CSV headers/units in place (idempotent) and regenerates the *_means.html. VTK arrays with "(-)" get m^3/m^3 (fractions), id or code in vtkio.unit_of. No plateau no longer drops results: flow without a mean-velocity plateau averages the last max(window, 25%) of the run (steady_method "fallback (not steady)"); a(t)/S(t) kinetics without a plateau use the last-window mean ("... (no plateau, last window)"); series_row falls back to the last samples when none are after the start time.
- Case settings (case_settings, *_settings.csv, Cases tab) include per impeller the <diameter> from input.xml, D/T, tip speed, Re = N D^2/nu_c, Fr, We = rho_c N^2 D^3/sigma, Vi = (rho_c/rho_d)^0.5 mu_d N D/sigma and the d32 correlations HIM eq. (12-30) D 0.053 (1 + 3 phi) We^-0.6 and eq.
